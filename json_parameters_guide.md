# Памятка по параметрам JSON задачи №2

Файл `data/task_02_social_network_config.json` является единственным источником исходных данных, допущений, сценариев, ограничений и настроек отображения. После изменения JSON Notebook выполняется сверху вниз.

## Реквизиты и источник

| Параметр | Назначение |
|---|---|
| `task_id`, `title` | Формируют заголовок задачи. |
| `student_name`, `group`, `date` | Реквизиты работы. |
| `project_name` | Название анализируемого проекта. |
| `source` | Номер лекции, страницы, источник задания и методическое примечание. |

## Основные экономические параметры

| Параметр | Что означает | На что влияет |
|---|---|---|
| `market_potential_users` | Потенциал рынка | Верхняя граница пользовательской траектории. |
| `initial_users` | Начальная база | Месяц 0 и срок достижения порога. |
| `growth_before_critical` | Рост до порога | Траектория, CAC на новых пользователей и критическая масса. |
| `growth_after_critical` | Рост после порога | Траектория после перехода через критическую массу. |
| `network_value_coefficient...` | Коэффициент `k` | Потенциальная ценность `V(N)=k×N²`. |
| `monthly_maintenance_cost_rub` | Ежемесячное поддержание | Прибыль, критическая масса и NPV. |
| `cac_rub` | CAC из условия | Строгий базовый сценарий. |
| `arpu_rub_per_user_month` | Выручка с пользователя | Доход, прибыль, критическая масса и NPV. |
| `analysis_horizon_months` | Горизонт | Число расчётных периодов. |
| `annual_discount_rate` | Эффективная годовая ставка | Через неё рассчитывается месячная ставка. |
| `monthly_discount_rate` | Справочное значение месячной ставки | Используется, если отключён автоматический пересчёт. |

## Сценарии

`operational_scenario` содержит отдельную управленческую гипотезу снижения CAC. Она не заменяет CAC из условия.

`scenarios` содержит варианты темпа роста. В каждом варианте задаются `growth_before` и `growth_after`; для каждого сценария заново рассчитываются пользователи, критическая масса, прибыль и NPV.

`combined_scenario` задаёт один согласованный вариант изменения нескольких параметров. В него входят ARPU, CAC, темпы роста, поддержание и целевой NPV.

## Цели и ограничения

`analysis_targets` задаёт нулевой NPV, целевой NPV, желаемое ускорение и целевую прибыль.

`scenario_constraints` задаёт диапазоны поиска ARPU, CAC, темпа роста и поддержания. `fixed_fields` можно использовать, если параметр нельзя изменить в управленческом сценарии.

## Допущения

В массиве `assumptions` для каждого допущения указаны название, значение, единица, источник, возможность редактирования и обоснование. В текущей модели отдельно зафиксированы отсутствие churn, трактовка ARPU как выручки и интерпретация закона Мэткалфа как потенциальной ценности.

## Чувствительность

`relative_values` содержит относительные изменения факторов относительно базового сценария. Каждый фактор изменяется отдельно. Это отличается от `combined_scenario`, где несколько параметров меняются одновременно.

## Валидация

Секция `validation` содержит положительные поля, неотрицательные поля, диапазон долей и правила согласованности. Notebook проверяет:

- начальная база не превышает рынок;
- горизонт в месяцах согласован с годами;
- ставки и темпы находятся в допустимом диапазоне;
- затраты, CAC и ARPU не отрицательны.

## Отображение и экспорт

`display` задаёт масштаб денежных графиков, число знаков, DPI и палитру. `charts` включает или отключает отдельные графики. `export` содержит имена файлов и исключения для архива.
